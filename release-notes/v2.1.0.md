# v2.1.0: media storage keys move into Studio, encrypted

Nothing breaks on upgrade: installs using S3_* env vars keep working as before.

## Storage under Settings > Integrations

A new **Storage** tab lets a Super Admin enter S3-compatible storage (Cloudflare
R2, AWS S3, Supabase Storage, MinIO) in Studio instead of env vars.

- The keys are checked with a test upload before they're saved, so a typo can't
  break uploads.
- The secret is stored encrypted with `SECRETS_ENCRYPTION_KEY`, like every other
  integration, and is never shown again. A leak of the host's env vars alone no
  longer exposes the bucket.
- Changes take effect without a restart.
- Already on env vars? Open the tab and save: leave the key fields blank to copy
  the current keys, or enter new ones. Then delete `S3_ACCESS_KEY_ID` and
  `S3_SECRET_ACCESS_KEY` from your host. The tab reminds you while they're still
  set.
- Only a Super Admin can change it, because storage serves every workspace on the
  install.

For R2, use an API token with Object Read & Write on that one bucket.

## Fixes

- `STORAGE_DRIVER=s3` with the S3 key vars removed no longer stops the API from
  starting; it logs a warning and uses the keys saved in Studio.

One small migration (adds the storage integration type), applied on boot.
