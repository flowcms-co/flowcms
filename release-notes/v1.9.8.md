# v1.9.8: bulk field updates in the agent API

Changing one nested field on many entries used to mean reading each entry,
copying the whole component and sending one PATCH per entry. Now it is one
request:

```
PATCH /api/agent/:type/bulk
{
  "where": { "slug": ["a", "b"] },
  "set": { "heroSection.subheadline": "Serving {CityCount} cities." },
  "dryRun": true
}
```

- `where` is optional and can filter by `slug`, `id` and `status`. Leaving it
  out, or sending `{}`, means every entry of the type.
- `set` takes field paths (`heroSection.subheadline`, `faq[0].answer`). Each
  path is deep-set, and every other key at every level is kept.
- Each entry is updated exactly as a single PATCH would be:
  - A draft entry is edited in place.
  - A live entry gets the change on its draft, on top of any edits already
    pending; its live page is unchanged until publish.
  - Status never changes, and only `content.update` is needed.
  - Versions, the activity log and webhooks follow as usual.
- Entries already holding the value are skipped.
- `dryRun` lists each entry's slug, status, and old and new values, and writes
  nothing.
- The response is `{ matched, updated, skipped, failed: [{ slug, error }],
  entries }`. One entry failing doesn't stop the rest.
- Up to 500 entries per request.
- Also in `@flowcms/client` as `bulkSet()`, and in the API reference on
  Settings › Developers.

As with any edit, an entry whose meta title is empty gets its title as the meta
title when it is saved.

No migrations, no config changes.
