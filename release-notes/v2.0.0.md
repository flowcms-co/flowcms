# v2.0.0: locked-out recovery, and the agent API can change the content model

Nothing breaks on upgrade: existing tokens, env vars and data work as before.

## Recover a locked-out admin

If nobody can sign in and no email provider is set up, the reset email never
leaves the server. Until now the only fix was a hand-written script. Now:

- `node apps/api/dist/recover.js reset-password --email you@example.com`, run on
  the server (`railway ssh`, `docker exec`, Render Shell), prints a one-hour
  reset link. Add `--set-password` to type a new password instead. Both sign the
  account out everywhere and add an `auth.password_reset_cli` event to the
  activity log.
- Hosts without a shell can set `FLOWCMS_RECOVERY_EMAIL` and
  `FLOWCMS_RECOVERY_PASSWORD`. The API applies them once on boot and warns on
  every boot until they're removed. Both are optional; nothing new is required.
- When a reset email isn't sent, the API log now says so and names the command.
  The forgot-password page answers the same way whether or not the account
  exists.
- Studio shows a banner to anyone who manages integrations while no email
  provider is set up: password resets and invites go nowhere until one is.

See [docs/RECOVERY.md](../docs/RECOVERY.md).

## Agent API: the content model

Agent and Admin tokens can now read and change types, components and fields
under `/api/agent/model/...`, using the same code as Studio's Schema Builder.

- Three new opt-in scopes under **Settings > API keys > Extra access**:
  `model.read`, `model.update` and `model.delete`. Existing tokens, including
  full-access ones, get none of them.
- Removing fields or types, changing a field's type, and changing page routing
  need `model.delete`. Changes that drop stored values also need `?confirm=true`;
  without it you get a summary of how many entries hold a value. Every write
  takes `?dryRun=true`.
- Changes appear in the activity log as `model.*` events, with the token named.
- `@flowcms/client` adds `flow.model.*` helpers.

See [docs/AGENT-MODEL-API.md](../docs/AGENT-MODEL-API.md).

## Fixes

- The setup wizard's password fields no longer let iOS and macOS keyboards
  capitalise, autocorrect or curl-quote a password while it's shown. Before,
  the first admin password could be saved with characters you didn't type.

No database migrations. Pull the new image and restart.
