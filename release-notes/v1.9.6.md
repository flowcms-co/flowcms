# v1.9.6: activity log, safe rollback, media in the agent API, and a master rollback

## Activity log: every change, every actor

- Every content action is recorded: create, edit (each real save), submit,
  approve, request changes, schedule, publish, unpublish, discard draft, slug
  change, restore, delete and restore from Deleted items. Also users, role
  changes, roles, API tokens (including access changes), webhooks, content model
  changes and all media actions.
- Each row has the actor (user name and role, or the API token's name, such as
  "City pages script (API token)"), the entry's title, slug and type at that
  moment, the version before and after, the time, the visitor's IP and browser,
  and for edits the field diff (path, before, after), for example
  `faq[0].answer`.
- Append only: there is no edit or delete route, and the database refuses an
  update to a logged row.
- **Real IPs.** The all-in-one image (Railway, Render, Fly) now trusts its own
  proxy and the platform edge, so the IP is the visitor's, not `127.0.0.1`.
  `TRUST_PROXY` also accepts a list of subnets.

## Settings › Activity (Super Admin)

- The full log with paging and filters: person or token, action, content type,
  entry, date range, and search by title or slug.
- Click a row for its diff, browser, version and details.
- CSV and JSON export with the same filters (Pro `audit_export`). The Security
  page links here instead of pointing at a missing export button.
- Retention (12 months minimum) and alerts. When alerts are on, email and the
  new `activity.alert` webhook fire for: publish or unpublish of a live page,
  slug change, delete, restore, role change, new API token and master rollback.
- **Deleted items:** deleted entries and files are kept for 30 days, with
  restore. An entry comes back with its versions and links, as a draft.

## Editor

- **Activity tab:** the entry's own history, with diffs.
- **Versions tab:** each version shows who made it and whether it was a draft
  or went live. Autosaves by one person merge into one draft version, so real
  history isn't pushed out (50 versions are kept, up from 10).
- **Opening a version** shows a read-only preview and its diff against the live
  page: changed fields only, text diffed word by word, images before and after.
- **Restore** asks for confirmation and takes an optional reason. You can
  restore as a draft (goes through review) or restore and publish now (fires
  `content.published`), and pick only some fields (for example only `faq`).
  A restore always adds a new version noted "restored from v41".
- Restoring needs the new **Restore** permission: Super Admin has it, and
  other roles only when given it. Refused attempts are logged.
- **Review tab:** a full sign-off log of every submit, decision, publish and
  restore, across all review cycles.
- **Schema panel:** no longer implies "BlogPosting" when no type is set. Adds
  Service and LocalBusiness.

## Agent API

- `GET /agent/activity` (content and media events), plus
  `GET /agent/:type/:id/versions` and `/versions/:v` (with diff).
- `POST /agent/:type/:id/versions/:v/restore` needs the `content.restore`
  scope.
- **Media:** `GET /agent/assets` (search, folder, type, minimum width and
  height, unused, missingAlt, tag), `/assets/:id`, `/assets/:id/usage` (entries
  and field paths).
- `POST /agent/assets` takes a multipart file or `{ url }`, with alt, caption,
  folder and tags. The same bytes return the existing asset.
- `PATCH /agent/assets/:id`, and `PATCH /agent/assets` with `{ items }` for
  many at once.
- `POST /agent/assets/:id/replace` keeps the id and repoints every entry using
  the file.
- `DELETE /agent/assets/:id` is refused while the file is in use unless
  `force=true`; it goes to Deleted items.
- `/agent/asset-folders`: GET, POST, PATCH, DELETE.
- New token scopes `content.restore`, `media.read`, `media.write` and
  `media.delete`. They are opt-in: neither `*` nor an existing token has them.
  Grant them under Settings › Developers › API keys › Access.
- New webhooks: `content.restored`, `media.created`, `media.updated`,
  `media.replaced`, `media.deleted`, `activity.alert`, `workspace.restored`.
- **Upload limits** (max size and allowed types) are now a setting under
  Settings › Content › Uploads. SVG stays refused.

## Safety net: master rollback (Super Admin)

- Settings › Workspace › System has whole-workspace snapshots of all content
  types, entries, reviews, relations, media and folders.
- Snapshots are taken daily (only when something changed), before any bulk
  delete of 5 or more items, on demand, and before every rollback.
- Snapshots use Brotli at maximum compression and are kept for 2 days.
- "Roll back to this" restores the workspace in one step. The state just before
  is snapshotted, so a rollback can be undone. Files added since go to Deleted
  items, never out of storage.
- Users, roles, tokens and settings are not touched.
