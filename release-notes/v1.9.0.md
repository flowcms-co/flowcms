# v1.9.0: reference pickers name their type and create entries; no stray Body editor

## Reference pickers

A Reference field that links to one content type now names it: "Search
tags…", "Search cities…", and "No tags yet" when the type is empty.
Fields that link to several types keep "Search entries…".

Options show just their label. The slug appears only when two options
share a label, to tell them apart.

Type a name that doesn't exist yet and the picker offers Create tag
"…" as its last option; press Enter or click it to create the entry
and link it. The option appears only on single-type fields and only
for users who can create content of that type. The new entry gets the
typed text as its title, a unique slug, and the same text in any
required Text field; if the type has other required fields, the full
editor opens in a new tab instead. Before offering to create, the
picker asks the server for an entry with the same title or slug
anywhere in the type and shows it on top instead, and the server
checks again when creating, so two editors typing the same tag at once
end up with one tag.

New entries are drafts. Any linked entry that isn't published carries
a Draft badge, with a note that the delivery API leaves it out until
it's published (or approved and published, where approval is
required). This works the same in Dynamic Zone sections.

## Body editor on field-less types

A content type with no fields no longer gets the Body editor, so
taxonomy types like tags have a clean editor and saving them never
writes a body. The Body editor shows for a type with a rich text field
named body, for an entry that already holds body text, or for a type
with the new **Free-form page** switch on (Schema Builder, Content
types, below the URL pattern). New types start with it off.

Nothing changes for existing workspaces: the upgrade migration turns
Free-form page on for every field-less type where at least one entry
already has body content. Field-less types without body content stay
off. The migration logs each type it switched on as a WARNING line
("free-form page switched on for content type …") in the Postgres
server log, for example `docker logs flowcms-postgres`. To list them
at any time:

```sql
SELECT "workspaceId", "name" FROM "ContentType" WHERE "schema" ->> 'freeFormBody' = 'true';
```

## Notes

One migration (20261001090000_free_form_body), applied automatically
on boot. New API routes: GET /entries/match, and `reuseExisting` on
POST /entries. No config changes, no new environment variables.
