# v1.8.9: the Schema Builder asks before trimming blocks

Since v1.8.6, making a repeatable component field single converts each
entry to its first block and drops the rest, reporting which entries
were affected. The report was returned and logged but never shown, so
the person saving saw only "Saved".

The change now asks first. Saving a schema that would drop blocks is
refused until it has been acknowledged, and the Schema Builder shows a
dialog listing the entries and how many blocks each would lose, with
Cancel and Keep only the first block. Cancel leaves the schema unsaved
and the entries untouched. Pending drafts are counted too. A change
that loses nothing, including going from single back to repeatable,
saves without asking.

For scripts and integrations: the same request now gets a 409 with the
affected entries and must send acknowledgeDataLoss: true to proceed.
