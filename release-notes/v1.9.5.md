# v1.9.5: opening an entry no longer changes it

## Opening a published entry created a draft that damaged its links

Opening a published entry in the editor, without typing anything, saved
a draft within seconds. The draft marked every link in rich text
`target="_blank" rel="noopener noreferrer nofollow"`, wrapped list
items in paragraphs, added an empty paragraph and rewrote `&` as
`&amp;`. An editor who then made a real change and published would
have shipped `nofollow` on the page's internal links.

- **Opening is not editing.** Loading an entry never saves it. The
  editor compares its content with what was loaded, and only a real
  change is saved. The server also ignores a save that changes
  nothing: no draft, no new version, `updatedAt` untouched, and a
  pending approval stays as it is.
- **Links carry only what you set.** The editor no longer adds
  `target` or `rel` to links. Links to your own site (relative, or on
  the workspace's site URL) never get either. For links to other
  sites, the link menu has two options, both off by default: "Open in
  new tab" and "nofollow".
- **Stored HTML is kept as written.** Loading and saving unchanged
  content returns it byte for byte. After a real edit, only the blocks
  you changed are rewritten; every other block keeps its stored bytes.
  An edited list is no longer given paragraphs inside its items unless
  it already had them, and no empty paragraph is appended.
- **Warnings.** The editor shows a warning, with a "Remove nofollow"
  button, when an entry's links to your own site are marked nofollow.
  The SEO audit has a new finding, "Internal links marked nofollow",
  with a one-step fix per page or for all affected pages.
- **One-off repair.** The Content page shows a notice when published
  entries have unpublished changes that are only this formatting, and
  offers to discard them. Each draft is re-checked first; drafts with
  real edits are never touched, and the live pages stay as they are.

Within a block you do edit, the editor's own formatting applies to
that block (for example a bare `&` becomes `&amp;`), which renders the
same.

## Reference picker

- The options shown always match what is typed, by title or slug.
- An empty field reads "None selected". "No entries yet" appears only
  when the referenced type really has none.
- Clicking an option selects it on press, and arrow keys with Enter
  select the highlighted option.
- For a multiple reference, picked entries are chips that can be
  reordered by dragging or with the arrow buttons on each chip.
- The "create" option shows the type as a badge: Create "Rust" [Tag].

## Delivery API: project and limit referenced entries

Referenced entries were always delivered in full, so a few picks could
multiply a response's size.

- `?fields=` accepts `reference.field`:
  `?fields=title,slug,guides.title,guides.slug,guides.thumbnailImage`
  delivers each guide with only those fields (plus `id`, `slug` and
  `__type`).
- `?populate=none` delivers each reference as `{ id, slug, __type }`
  without reading its content. `?populate=guides,service` expands only
  the named Reference fields and delivers the rest as ids and slugs.
- With neither parameter, responses are unchanged.

## Agent API: live and draft side by side

- `GET /api/agent/:type/:id` now also returns `liveData` (what the
  public API serves) and `draftData` (the pending draft, or null).
  `data` is unchanged: the version an edit builds on.
- New: `GET /api/agent/:type/:id/draft-diff` lists each changed field
  path with its live and draft value, and says whether the difference
  is only editor formatting.
- `PATCH` merges: the fields you send replace those fields, and fields
  you leave out are kept. The merge is one level deep, so a list or
  nested object you send replaces the stored one whole. On a published
  entry the result is staged as the draft.

## Notes

No migrations, no config changes. New routes: GET
/entries/drafts/formatting-only, POST
/entries/drafts/formatting-only/discard, GET
/agent/:type/:id/draft-diff. New issue code LINK_INTERNAL_NOFOLLOW.

After upgrading, open the Content page once to discard any
formatting-only drafts left by earlier versions.
