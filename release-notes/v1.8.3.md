# v1.8.3: Agent tokens work again, and the author setting reaches the dashboard

## Agent tokens can be created from the studio

Creating an Agent token under Settings, Developers failed with "AGENT
tokens require explicit scopes". The API requires an Agent token to say
what it may do, so a token meant for reading can never write by
accident, but the form had no way to choose and sent nothing.

The form now shows what the token can do when you pick the Agent type:
read, create and edit content are ticked to start with, publish and
delete are not. At least one must be chosen.

If you created an Admin token as a stand-in, you can revoke it and
create an Agent token with only the permissions your agent needs.

## The token list says more

Agent and Admin tokens now show what they may do, either "Full access"
or the list of permissions. Tokens with an expiry date show when they
expire, or that they already have.

## Expiry dates are checked

A token could be created with an expiry date in the past, which made a
token that never worked. A date that could not be read caused a server
error instead of a message. Both are now refused with a clear reason.

## Author setting: dashboard and notifications

v1.8.1 let a workspace choose whether an entry's author is its original
creator or its latest editor, and let you pick an author by hand. The
content list followed that choice, but the dashboard and notifications
still went by the original creator. They now follow it too:

- Dashboard: your tasks, your published work, words this month, the
  weekly goal, the team table, the review queue and the activity feed.
- Notifications: approved, published, scheduled and changes requested.

The dashboard is cached for 15 seconds, so a change of author can take
that long to appear there.

## Webhooks

- A webhook could be saved without an address, so it could never
  deliver. An address is now required when creating or editing one.
- A deleted webhook could still send a test ping, or resend an old
  delivery. Both are now refused. Its delivery history is kept.

## Notes

No migrations, no config changes, no new environment variables. API
and studio.
