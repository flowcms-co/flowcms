# v1.8.0: deletes that stick on R2, and renaming assets

Deleting images on installs that store media in Cloudflare R2 (or
another S3-compatible store) could fail, and the image kept coming back
in the Assets library. The storage driver deleted files with a batch
request that current AWS SDKs sign with a CRC32 checksum instead of
Content-MD5, and some S3-compatible stores reject that. The request
failed, the asset stayed in the library, and the Assets page reloaded
without saying why.

Files are now deleted one at a time with a request every S3-compatible
store accepts, so single and bulk deletes work on R2 again. Assets that
got stuck can simply be deleted again after updating.

If storage ever does refuse a delete, the asset stays in the library so
nothing is left public but hidden, and the Assets page now shows the
reason instead of the image silently reappearing.

## Rename assets

The name in an asset's details panel is now editable. Press Enter or
click away to save, Escape to cancel. Only the name changes: the file's
URL stays the same, so pages that use the image are unaffected. The
file's real extension is always kept, and empty names, names with / or
\ and names over 200 characters are rejected with a message. Search and
the Duplicates filter use the new name straight away.

## Notes

No migrations, no config changes, no new environment variables. API
