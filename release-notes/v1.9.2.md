# v1.9.2: an audit that scales, honest schema and noindex findings, a tidy job panel

## The audit fetches fewer pages, not faster

A full run used to request every page from your site: 25 minutes for
1,400 pages, and far longer for large sites. The audit now avoids
fetching wherever it can.

- **Only what changed.** "Run audit" fetches a page only when
  something it is built from changed since its last fetch: the entry,
  an entry it references (a parent service, a city, a tag), its content
  type's schema or URL pattern, a reusable component it uses, or a
  newer `lastmod` in your sitemap. Every other page is re-checked from
  what was last fetched, with no request. A second run on an unchanged
  workspace makes no requests.
- **Re-check every page** is a separate button for an explicit full
  crawl. It runs in the background.
- **You see the cost first.** Before a run starts it says how many
  pages it will fetch and roughly how long that takes. A run can be
  paused, resumed or cancelled.
- **Pages that can rank come first.** Indexable pages in order of
  Search Console impressions, then other indexable pages, then
  noindexed ones. Results appear as pages are checked.
- **Large page types are sampled.** When more than 200 pages of one
  content type need fetching, the audit fetches 50 (a different 50 each
  run). If they agree on the JSON-LD types, canonical and robots tags
  the template renders, the rest are filled in from the sample and
  labelled "inferred from a sample". If they disagree, every page of
  that type is fetched.
- **A steady background check.** The stalest pages are fetched again a
  few at a time, so every page is verified within 14 days (Settings,
  Workspace, System) without anyone running anything.
- **The rate adapts.** It starts at 1 request per second, speeds up
  gradually while the site responds normally, up to a workspace maximum
  (10 per second by default), halves on any 429 or 503, honours
  Retry-After, and stays under `RateLimit` headers when the site sends
  them. Set the maximum equal to the start to hold a fixed rate.
- **Conditional requests.** Fetches send `If-None-Match` and
  `If-Modified-Since`, so an unchanged page can answer 304.
- **Change signals.** `POST /api/public/seo/signal` with a workspace
  API token accepts `{ "urls": [...] }` (these pages changed) or
  `{ "deployed": true }` (sample re-check of each page type). See
  docs/SEO-CRAWLER.md.

Nothing unverified is shown as clean. Every page shows when it was
last fetched; inferred results say so and are not counted as clean
pages; the Optimizer shows the oldest live check and, for sampled
types, "verified on N of M pages".

## Structured data findings

"No structured data" was raised on every page without Article schema,
including service and city pages that carry Service, FAQ and
Breadcrumb schema.

- "No structured data" is now raised only when a page has no JSON-LD
  at all.
- Article schema is expected only on article content (a blog page
  type), and when it is missing the finding says "No Article schema".
- The same rules apply when the audit reads entry fields instead of
  the live page, and JSON-LD the CMS derives from sections (FAQ,
  reviews, how-to) now counts there.

## Pages hidden from search

A noindexed page cannot rank, so it no longer buries the findings on
pages that can.

- Noindexed pages are shown as a count ("1,327 pages hidden from
  search"), outside the issue total and the score.
- Noindex is a warning only when the site contradicts it: the page is
  in the sitemap, gets search impressions, or is linked from the
  navigation. The warning says which.
- Noindexed pages are left out of the title, description, readability,
  schema, duplicate content and cannibalization checks.
- A noindexed page with no other findings counts as a clean page.
- Content types have a new switch, **Noindex is intended** (Schema
  Builder), which silences the warning for that type.
- The live crawler's Technical score follows the same rule.

## While an audit runs

- The Optimizer, the SEO dashboard's Issues Snapshot and the home SEO
  Health card show "Audit in progress, N of M" and only the pages
  already checked. Rows from the previous audit are no longer shown as
  current.
- Switching a content type to "not pages" removes its audit rows
  immediately.
- Each audit row records the rule set that wrote it. Rows from an
  older rule set are never shown; after an upgrade they are brought up
  to date in the background from the stored page facts, with no
  requests to your site.
- A row with no URL and no title is never rendered.
- A page that was checked before keeps its earlier result when a later
  fetch is rate limited.

## Job panel

While a job was running, the panel also listed finished jobs from days
ago, and closing one brought it back within five seconds. The panel
now shows only jobs that are queued or running, plus a job that
finishes while on screen until you close it. A closed job stays
closed. Closed jobs are remembered until the page is reloaded, and a
reload loads only running jobs.

## Notes

One migration, applied automatically on boot:
20261006090000_seo_incremental (PageAudit.fetchedAt, backfilled for
pages already fetched; Workspace.seoCrawlMaxRps and seoRecheckDays).
After upgrading, pages fetched under v1.9.1 are not fetched again
until they change or their 14 days are up.

Behaviour to know about:

- The crawl rate now rises above 1 request per second when the site
  allows it. To keep the fixed rate of v1.9.1, set the maximum to 1.
- A job summary reads "Checked N of M pages, X unchanged, Y fetched
  from the site, Z inferred from a sample".
- A sample re-check after a deploy marks pages outside the sample as
  inferred until the background check reaches them.

API changes: POST /seo/scan/jobs/run accepts `{ "mode": "changed" |
"full" }`. New routes: GET /seo/scan/plan, POST
/seo/scan/run/pause|resume|cancel, POST /public/seo/signal. GET
/seo/scan/issues adds `run`, `freshness`, `counts.noindexed`,
`counts.inferred`, and `fetchedAt` / `inferred` on each page. New
issue code SCHEMA_ARTICLE_MISSING. Content types accept
`noindexIntended`. PATCH /workspace accepts `seoCrawlMaxRps` and
`seoRecheckDays`. No new environment variables.

Known limits: the rate gate and run state are per API process (one
instance per site is assumed). Sampling compares JSON-LD types,
canonical and robots tags; a page type whose pages differ in any of
these is always fetched in full. Navigation links are read from the
homepage's `<nav>` and `<header>` only.
