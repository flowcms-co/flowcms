# v1.9.1: SEO audit reads the live site; dashboards show only real numbers

This release fixes the SEO dashboard, the AI Optimizer and the home
dashboards for headless sites, where the frontend builds titles,
descriptions, canonicals, alt text and JSON-LD itself. Findings came
from a real workspace with 1,615 published entries, where the audit
reported about 1,600 issues on 500 "pages" while the live pages were
clean.

## Site URL and real page URLs

Settings, Workspace, System has a new **Site URL** (your public
website). The crawl, PageSpeed and "View live" links use it, so they
work with or without Search Console. Existing workspaces get it filled
in from their Search Console property.

Every SEO surface now uses a page's real URL, built from its content
type's page type and URL pattern (for example
`/{service.slug}/{city.slug}` or `/resources/tags/{slug}`), instead of
"/" plus the slug. That covers issue lists, internal link suggestions
(existing links are now recognised), canonical fixes and the crawl.

Content types have a new switch, **Entries are pages on the site**
(Schema Builder, Content types). Only page types are audited. It is on
by default, except for reference types with no URL pattern (cities,
tags with no page of their own). Until someone sets the switch by
hand it follows that default, so adding a URL pattern turns it on. If
a type has a URL pattern but the switch is off, the Schema Builder
shows a prompt to turn it on.

## AI Optimizer and page audit

- The audit covers every published page of a page type, in a stable
  order, with no 500 cap. Counts, clean pages, schema, and
  cannibalization are computed over all of them.
- With a site URL set, the title, description, canonical, robots and
  JSON-LD checks read the page's live HTML. Entry fields are only the
  fallback for workspaces with no site URL. A page that cannot be read
  is listed under "Live page could not be read" with its HTTP status,
  instead of being reported as missing its tags.
- Title templates with tokens such as `{City}` are filled in before
  the length is measured. A description inherited from a parent entry
  counts as present.
- Image alt text is resolved the way the site gets it: the paired alt
  field first, then the asset's alt text. Top-level image fields are
  now checked, and plain text that starts with "Image" or "Media" is
  no longer mistaken for an image.
- "Fix with AI" for alt text works on the same images the audit flags
  (sections, components and image fields, not only the body), and
  writes each alt into its paired field or rich text.
- The canonical fix writes an absolute URL (site URL plus the real
  path) and is skipped when there is no site URL. Meta fixes leave
  inherited titles and descriptions alone.
- "Run audit" runs as a background job with progress, and reports
  pages checked, unchanged, not checked and failed.
- The audit requests live pages at 1 request per second per host by
  default (Settings, Workspace, System, "SEO crawl rate"). When the
  site answers 429 or 503 it waits for Retry-After, or backs off, and
  resumes. A page that answered 429 or a server error gets no
  findings: it is marked "not checked", left out of clean pages, and
  retried.
- Duplicate content compares up to 400 pages and internal links up to
  500. Both now pick the pages with the most Search Console
  impressions (or the most recently published when there is no Search
  Console data), and say "checked N of M pages" wherever the result
  appears, including when nothing was found.
- The Optimizer lists content types that have published entries but
  are not marked as pages, so a missed switch is noticed.
- The made-up "LCP 4.2s, sample data" issue is gone. When PageSpeed
  has no result the Optimizer says "PageSpeed unavailable" and why.

## Delivery API: asset alt text is the default

When an image's paired alt field is empty, the delivery API fills it
from the asset's alt text, and does the same for images in rich text.
Editing an asset's alt reaches the site within a minute, with no need
to re-save pages. Alt text an editor wrote on the page is never
replaced.

## PageSpeed and Core Web Vitals

- PageSpeed runs in the background, daily, for the homepage and one
  page per content type, on mobile and desktop. Results are stored per
  URL and shown per page with the Lighthouse performance score.
  Dashboards read the stored results and never wait on PageSpeed.
- INP is shown only when Google has field data for it. Without field
  data it reads "No field data" and is left out of the Speed score
  (it used to show Time to Interactive graded as INP). Total Blocking
  Time is shown as a separate lab metric.
- The Speed pillar lists the metrics behind its number and the URL and
  device tested.
- Failed runs are stored with their reason. When Google's shared quota
  is used up, the dashboard and the connector card say an API key is
  needed.

## Live crawler

- Only HTTP 200 pages are audited. Other responses are reported with
  their status ("blocked: 403").
- A crawl covers up to 40 URLs: the homepage, top Search Console
  pages, one page per content type, the sitemap and the CMS's own page
  URLs. It used to be 8, and only the homepage without Search Console.
- The stored crawl is served immediately and refreshed in the
  background. The score and issues endpoints share one crawl instead
  of running two.
- The crawler's user agent, `FlowCMS-SEO-Auditor/1.0`, is documented
  in docs/SEO-CRAWLER.md with what to allow on your firewall.

## Analytics and Search Console

- Sources sync when you connect them and then daily. Each connector
  card shows the last sync time and the number of rows stored.
- Connecting checks that the service account can read the property and
  says what it found. An account with no access no longer shows as
  Connected.
- The "Sample data" badge is gone. Empty cards say why: not connected,
  connected with no data yet, no GA4 hits, sync failed, or no access
  for your role.
- A pillar with no data shows a dash and the reason, not 0.
- KPI tiles honour the selected period and compare against the equal
  period before it. CTR is clicks divided by impressions and average
  position is weighted by impressions. KPI sparklines show real daily
  values.
- The "Data sources" footer lists what is actually connected, with the
  last sync or run for each.
- Without a backlinks provider the Backlinks card is titled "Referral
  traffic". The Top Keywords "Change" column and the AI platform
  "Change" column are removed until that history is stored.
- The Issues Snapshot badge reads "Page audit", not "Crawler".

## Home dashboards

- The hardcoded percentage changes and trend lines are removed from
  the admin and editor tiles. Tiles show a loading state or an error
  instead of a zero.
- "SEO issues" and the SEO Health card take their counts from the same
  issue set as the AI Optimizer, and one set of thresholds labels the
  score everywhere.
- "Ready to publish" includes approved changes to live pages.
- The content calendar shows what is scheduled or was published this
  week, and no longer goes empty over time.
- Recent activity is a real log of who created, edited, submitted,
  approved, scheduled, published, unpublished or archived each piece.
  It starts recording with this version.
- Search performance: the headline is labelled by its source (GA4
  sessions or Search Console clicks), the chart sums each bucket on an
  axis that fits small sites, periods are 7, 30 and 90 days, and the
  card works with GA4 alone.
- Editor dashboard: every row opens the right entry, "Due today" is
  now "Awaiting review", approved work has its own group, "View all"
  filters correctly, and recently published rows link to the live page.
- The weekly goal and streak count a piece once, on the day it first
  went live. Re-publishing edits and bulk imports no longer count.
- Quick suggestions reads every text field, says how many pages it
  scanned, and no longer says "All clear" when it could not scan.
- Dashboards respect per-role content types. Workspace-wide pipeline,
  activity and calendar are shown only to roles that can publish.
- "Today" and weeks follow the workspace **Time zone** (Settings,
  Workspace, System; UTC by default), chosen from a searchable list.
  Unknown zone names are rejected on save, and if a stored value is
  ever invalid the dashboards use UTC and the settings page says so.
- "View as" is labelled as a layout preview.

## Notes

Two migrations, applied automatically on boot:
20261005090000_workspace_site_url (Workspace.siteUrl, backfilled from
Search Console; Workspace.seoCrawlRps; PageAudit.live) and 20261005100000_dashboard_fixes
(Workspace.timezone, ContentEntry.firstPublishedAt).

After upgrading:

- The first audit re-checks every page, and audit rows for entries
  that are not pages are removed. With a site URL set it requests each
  page once from your site, at 1 request per second.
- Recent activity starts empty; there is no backfill.
- Imports already in the database count towards "published this week"
  until that week passes.

API changes: GET /seo/scan is paginated (`limit`, `offset`, default
100). New routes: POST /seo/scan/jobs/run, GET /seo/scan/alt/:id,
POST /seo/scan/alt/:id/apply. GET /seo/vitals returns stored results
with `pages`, `performance`, `tested` and `refreshing`. GET /seo/score
pillars carry `note` and `detail`. GET /seo/connectors adds `site` and
`pagespeed.needsKey`. GET /analytics/status adds `rows`; GET
/analytics/overview adds `previous`, `asOf` and caps `days` at 90.
GET /dashboard/summary drops `team`, `reviewQueue`, `totals`,
`my.tasks` and `my.published30d`, renames `my.dueToday` to
`my.awaitingReview`, and `pipeline`, `activity` and `calendar` can be
null. PATCH /workspace accepts `siteUrl`, `timezone` and
`seoCrawlRps`. GET /seo/scan/issues adds `counts.notChecked`,
`coverage` and `nonPageTypes`; GET /seo/internal-links adds `total`. No new
environment variables.

Known limits: duplicate-content detection compares 400 pages and
internal link suggestions 500 (see above). The time zone list uses
the runtime's names, so a few zones appear under their older name
(Asia/Calcutta for Asia/Kolkata). "Words written" is
the size of the pieces you edited in the last 30 days, not a diff.
